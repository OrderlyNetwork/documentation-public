---
title: "Orderbook"
description: "Subscribe to full depth-100 orderbook snapshots for a symbol via WebSocket, pushed every second."
---

`{symbol}@orderbook` depth 100 push every 1s

```json
{
  "id": "clientID2",
  "topic": "PERP_WOO_USDC@orderbook",
  "event": "subscribe"
}
```

**Parameters**

| Name          | Type   | Required | Description           |
| ------------- | ------ | -------- | --------------------- |
| id            | string | Y        | id generate by client |
| event         | string | Y        | subscribe/unsubscribe |
| topic         | string | Y        | `{symbol}@orderbook`  |
| params.symbol | string | Y        | `{symbol}`            |

## Orderly Predict

For a Predict round symbol (`<binary_symbol>`), the push additionally includes `down_asks` and `down_bids`. `asks` and `bids` keep their existing UP-side semantics and payload. Each `down_asks` price is `1 - bid price`, and each `down_bids` price is `1 - ask price`; quantities are unchanged.

```json Subscribed Message
{
  "topic": "<binary_symbol>@orderbook",
  "ts": 1614152140945,
  "data": {
    "symbol": "<binary_symbol>",
    "asks": [[0.56, 120]],
    "bids": [[0.55, 100]],
    "down_asks": [[0.45, 100]],
    "down_bids": [[0.44, 120]]
  }
}
```

Non-Predict symbols do not return `down_asks` or `down_bids`. See [Market Data](/build-on-omnichain/orderly-predict/market-data#order-book) for how the UP and DOWN sides relate.
